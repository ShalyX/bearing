# Design Plan

## Product character

A serious decision instrument for ordinary users, not a crypto dashboard, agent social feed, or generic SaaS admin panel.

## Design promise

Outcome-first, jargon-free, wallet-late, and usable without outside instructions.

## Surface progression

- Landing: explain the simple promise and present four jobs.
- Category workspace: explain one job, its risks, live context, and available supply.
- Agent detail/compare: align evidence, permissions, cost, and risk.
- Job surface: show live execution, receipts, and next actions.

## Main composition

A decision lane:

1. Job context and plain-language objective
2. Live state and constraints
3. Agent supply and comparison
4. Evidence ledger
5. Clear activation action

A category workspace is not an empty agent-card grid. It remains useful when supply is absent by explaining the job, qualification requirements, supported protocols, and provider submission path.

## Visual system

- Canvas: `#08090a`
- Restrained dark panels with hairline borders
- Neutral high-contrast text hierarchy
- One indigo action accent
- Green, amber, and red only for truthful status
- Inter or Geist for interface text
- Mono for IDs, hashes, timestamps, and evidence values
- Tabular numbers for prices, latency, and performance

Avoid gradients, neon crypto styling, fake charts, decorative metric slabs, badge spam, and template feature grids.

## Signature interaction

The evidence-backed agent decision: compare capability, live status, recent execution, permissions, cost, and risk in one readable surface before activation.

## Required states

Loading, no verified agents, offline agent, stale data, partial data, comparison selection, test unavailable, wallet required, approval pending, running, confirmed success, failure, timeout, cancellation, and payment failure.

## Accessibility and usability

- Mobile-first composition
- Keyboard focus states
- Semantic headings and landmarks
- Labels for icon-only controls
- Never use color as the only status signal
- Respect `prefers-reduced-motion`
- Two-minute cold-start journey without documentation or a product tour
- User must be able to explain what will happen before wallet approval

## Visual gate

Before UI sign-off, run the real browser journey, inspect desktop and mobile screenshots, verify all empty/error/disabled states, and remove one unnecessary visual accessory.
